# 100 Mbps 流式引擎实施计划

## 1. 成功标准

| 项目 | 标准 |
| --- | --- |
| 架构 | FUSE 只负责文件语义，流式状态集中在 `internal/stream` |
| 调度 | 1 MiB 块持续 Worker 队列，无整批等待 |
| 缓冲 | 128 MiB 低水位、256 MiB 目标、32 MiB 后向保留 |
| 缓存 | 320 MiB 内存 + 2 GiB 磁盘，可配置和有界 |
| Seek | 旧 epoch 可取消，P95 恢复小于 3 秒 |
| 抗慢块 | P0 受限竞速，不重复发布 |
| 测试 | 100 Mbps 模拟、故障注入、race、vet、Docker 构建通过 |

## 3. 实施原则

- 测试先行，每个调度行为先有可复现失败用例。
- 不同时维护旧句柄预取和新 StreamManager 两套逻辑。
- 所有缓存有明确字节预算和取消边界。
- 不使用真实时间长睡眠做核心单元测试，调度器注入时钟或阈值。
- 正常日志保持精简，逐次 FUSE Read 仍由 trace 开关控制。
- 不修改目录刷新、OAuth、删除和上传计划范围。
